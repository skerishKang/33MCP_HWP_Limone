## 설치와 연결
1. Windows 10/11, 한글 설치/COM 등록, Python 및 `pywin32` 구성이 필요하다.
2. 설치 명령 및 MCP 설정은 `INSTALLATION_GUIDE.md`를 참고하되, 현재 `main`의 구형 절대 경로 예제는 그대로 사용하지 않는다. 수정안은 Draft PR #2의 가이드를 참고한다.
3. 클라이언트 표준 `stdio`는 단 하나의 서버 진입점 `advanced_hwp_server.py`에 연결한다.
4. 프로그램 연결만으로 HWP를 열지 않는 것을 목표로 하고, 실제 문서 조작 호출에서 COM 초기화한다.
5. 실사용 최초 테스트는 합성 문서 생성→텍스트 입력→**명시적 파일 경로**에 저장→탐색기에서 파일 확인→한글로 재열기 순서다.

## 일상 점검
- 활성 브랜치/HEAD, 최근 PR과 CI 상태, 알려진 외부 이슈(#1) 확인.
- 사용 중인 Python/HWP/클라이언트 버전을 사용자 보고와 함께 기록.
- COM 실행 프로세스 고아 인스턴스, 문서 잠금, 임시 파일 및 백업 잔재를 확인하되 자동 강제 종료/삭제 금지.
- 저장 성공은 COM return value, 파일 존재 및 비어 있지 않음, 실제 재열기로 교차 확인.
- 로그에는 고객 문서 내용·인증정보·개인 식별 경로를 기록하지 않는다.

## 장애별 원인과 해결
| 현상 | 점검할 원인 | 바로 할 조치 |
|---|---|---|
| MCP 연결 직후 HWP 자동 실행 | 구형 서버의 eager init | 실제 실행 경로가 PR #2의 lazy-init 수정 대상인지 확인; client 설정 경로 교체 |
| HWP COM 생성 실패 | 한글 미설치/COM 등록/비트수/권한·세션 | 동일 계정에서 한글 수동 실행, 등록 상태 확인, 버전과 예외 메시지 수집 |
| 파일 저장 성공 메시지인데 파일 없음 | 구형 SaveAs 처리/경로 오류/사용자 취소 | 출력 폴더 존재·권한, 실제 API 결과, 산출 파일 및 재열기 확인 |
| HWP 표 편집 '성공'인데 내용 그대로 | 로컬 34 driver의 스텁 | 구현 완료로 보지 않고 #7 실제 API와 검증 추가 |
| 문서 변환 정확도가 높게 표시됨 | 로컬 35 simulated 평가 | #8 실측 샘플/출력 비교 후에만 수치 사용 |
| 문서 편집 중 중단 | 파일 잠금/동시 COM/중단된 작업 | 원본과 백업 보존, 원인 기록, 복구 검증 전 재실행 제한 |

## 백업과 복구 원칙
- 기본은 원본 불변·새 출력 경로. 복구 기능이 실제로 작동한다는 증거 없이 '안전한 자동 롤백'을 약속하지 않는다.
- 원본·사용자 파일을 사고 없이 유지하고, 임시 작업 폴더가 있을 경우 작업 종료 후 개별 확인.
- 34번 롤백은 물리 백업과 저널의 실효성이 모두 검증된 후 활성화.
- 릴리스 결함 시 이전 검증 태그로 복귀하되 사용자 데이터 변환은 자동 역변환하지 않는다.
